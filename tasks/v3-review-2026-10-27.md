## Findings requiring action

1. **P1 — Copying evidence still changes cohort support (item 6).**
   [CohortInference.groovy:624](../gspa-core/src/main/groovy/gspa/integration/cohort/CohortInference.groovy#L624)
   divides each cluster's support by its raw member count. In a cluster with two
   distinct members, copying one member changes its influence relative to the
   other. A fresh replay of the archived heterogeneous-cluster case yields
   smoothed support 0.500000, 0.583333, 0.650000 and 0.678571 for 0, 1, 3 and 5
   copies. Effective independent N remains 1. Fourteen model features change;
   their fitted logistic-margin contribution changes by 1.59597 at five copies.
   That margin calculation is a mechanism check, not a calibrated biological
   prediction. Deduplicate identical evidence consistently within clusters while
   preserving genuinely distinct members, and add this case to the regression
   gate. The passing 18-genome duplicate control does not cover this case.

2. **P1 — The requested learned no-candidate outcome is unavailable (items 4, 7).**
   Both current contract-v3 model artifacts contain `locus_model.trained=false`.
   [The logistic artifact](../benchmark/v3/results/cohort-contract-v3/models/model_logistic.json)
   records zero no-correct-candidate training groups and one single-positive
   group. The loader correctly leaves the locus layer unavailable; ordinary
   probability thresholding does not implement the requested trained null
   competition. Acquire complete independent locus/role labels and train and
   validate this layer before declaring these requirements complete.

3. **P1 — The reported agent superiority/accuracy is not validated (item 11).**
   At `498560f`, `evaluate_stage3_agent.py:270` embeds the true carrier in the
   public anomaly ID; lines 312–313 and 385–386 supply hard-coded classifier
   probabilities. This was verified directly in the release source. The current
   evaluator replaces that generator, but its
   [validation artifact](../benchmark/v3/results/stage3-agent-evaluation-v2/validation.json)
   has zero matching experimental assignments in calibration and test. All seven
   frozen policies abstain on all 158 test cases. The old accuracy claims cannot
   support completion, and the replacement demonstrates execution rather than
   biological accuracy. Evaluate on independently labelled unresolved cases.

4. **P1 — The planner benchmark does not test masked function recovery (item 12).**
   [run_planner_benchmark.py:160](../benchmark/v3/run_planner_benchmark.py#L160)
   obtains target reactions from the existing gene assignment and uses them to
   construct proximity evidence. This can test condition selection for known
   assignments; it cannot validate discovery of the withheld function. The new
   masked-assignment path has useful synthetic solver and invariance checks,
   but held-out biological recovery, partner evidence and product validation
   remain outstanding. Keep the two claims separate and run the requested
   assignment-masked, equal-budget evaluation.

5. **P2 — AntiFam evidence disappears at the integration boundary (items 2, 3).**
   `AntiFamPredictor` emits `PSEUDOGENE` annotations with source `antifam` and no
   explicit evidence type. That source is absent from `SOURCE_TO_TYPE`, so
   [ClaimExtractor.groovy:87](../gspa-core/src/main/groovy/gspa/integration/ClaimExtractor.groovy#L87)
   returns null. A fresh call through the built JAR confirms this. Preserve a
   typed quality signal through export/integration and explicitly define its
   effect on functional evidence; merely adding a pseudogene as an unrelated
   positive function claim would not solve the issue.

6. **P2 — Reaction-context ablations do not exercise their advertised mechanism
   (items 1, 5).**
   [run_training_cohort_ablations.py:62](../benchmark/v3/run_training_cohort_ablations.py#L62)
   still writes `-` for every gaps input. The historical RLC comparisons therefore
   had no eligible work, as the corrected report acknowledges. The new execution
   checks reject a skipped required stage, which is useful, but does not supply
   a valid ablation. Provide real eligible gaps and rerun the matched comparisons.

7. **P2 — Community simulations are not connected to candidate inference
   (items 8, 9).**
   [CommunityStage.groovy:68](../gspa-core/src/main/groovy/gspa/integration/contextbridge/CommunityStage.groovy#L68)
   explicitly exports `features_for_candidates: none`. Its conservative refusal
   to turn growth rescue into an enzyme assignment is appropriate. However, the
   requested competing external-supply explanation and measured reduction in
   false enzyme assignments have not been implemented/validated end to end.
   Define the appropriate evidence contract and independently test attribution,
   exchange and transport effects.

The current model evaluation also does not establish general functional accuracy:
only 462 of 608 table-test rows have supported input profiles. Its target is
reference-annotation support under a declared closed-world policy. The separate
whole-genome logistic policy obtains 25/27 supported calibration calls but only
6 supported and 6 unverified intact test calls. Unverified does not mean
experimentally false. The tree policy abstains for both EC and GO. These limits
are explicit in the artifacts and must accompany any performance claims.

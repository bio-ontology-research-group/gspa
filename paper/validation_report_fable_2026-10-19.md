# Validation of the GSPA manuscript, analysis, and code (2026-10-19)

Scope: `paper/main.tex` at commit c147097, `results/*.tsv`, `benchmark/**`, `scripts/**`, and the Groovy/Java pipeline. Five independent audits (Table 1; Table 2 / Fig. 2; Tables 3–7; Stage 3 + AllTheBacteria; code vs Methods) plus my own checks of the bibliography, figures, and selected TSVs. The JVM build and test suite pass (`./gradlew clean test`: 433 tests, 0 failures). Every Methods constant matches the code.

Severity: **A** = fabricated / untraceable / wrong direction, must be removed or regenerated; **B** = real result described incorrectly; **C** = reproducibility and reporting.

## A. Results that are not supported by any file, script, or run

1. **Table 2, external-baseline block (8 rows × 12 cells).** No file or script produces C_ess, pathway/complex coherence, violations, audit score, or perturbation survival for HMMER, PGAP, DIAMOND, metagenomic-deepFRI, InterProScan, or ESM-2 kNN; `04_run_perturbation.py` only perturbs the nine bench9 genomes under GSPA configs. Only 4/96 cells match the single (transcribed) panel TSV; the consistency column contradicts the caption's own formula (HMMER V=14 printed as 0.9850); CAFA F-max values disagree with Figure 2d, which is drawn from the TSV. All rows were added in commit 3310b97 ("eliminate flat/n/a cells"). *Fix (applied):* block commented out; Table 2 now contains the ablation only. *To do:* if external pipelines are to be compared on structural metrics, run `gspa evaluate` and the perturbation script on their outputs and commit the raw JSON.
2. **Table 5, Protocol H and gapseq-density rows.** Printed values (e.g. ≤30%: 11/2, pool Hit@1 100%) exist nowhere; `pillar2_lro15_summary.tsv` gives 94/27 → 51.9%, 57/12 → 58.3%, 37/3 → 33.3% pool Hit@1, i.e. the opposite trend. The 256-cohort and B. subtilis gapseq rows have no TSV counterpart. Added in 3310b97. *Fix (applied):* table rebuilt from the TSV; text now reports the decline under masking (Fig. 6c already showed it).
3. **Table 4, S. cerevisiae and means.** Removal/relaxation F-max 0.9604/0.9592 are not in `pillar3_relax_vs_remove.tsv` (0.9971/0.9737). With TSV values the six-species means tie at 0.9629, so "relaxation outperforms deletion" does not hold on F-max. *Fix (applied):* values and claim corrected (relaxation retains recall/IC in four species; deletion wins in yeast and moss). The endogenous-row removal F-max 0.7084 was a formula (`max(e1, e5-0.0008)`, `run_pillar3_eukaryotic_anatomy.py:843`), and 0.7117 was Stage 1 iteration 1, not relaxation; "1,009 high-confidence violations" is in no file. *Fix (applied):* row reduced to measured values (0.7096 → 0.7109).
4. **106-BGC table (Suppl. Table S10) and 97-MAG table (S11).** No generator; the only raw antiSMASH file has four classes with recalls 0.05–0.17 and a skipped terpene class, contradicting the TSV. *Fix (applied):* removed from the main text; Fig. 3d remains in the figure file and must be dropped at regeneration. *To do:* delete S10/S11 or regenerate with committed scripts and inputs.
5. **AllTheBacteria (Section 2.9, Fig. 7, Suppl. S7/S17/S18).** "Rescues", "violations", "gaps", and "singleton pruning" are computed by a Python heuristic in `stageC_whole_genome_integrate.py:540-655` (e.g. `new_p = min(0.88, s0+0.24)`), never from the GSPA integrator, which ran on only 20 genomes per batch (`java_runtime_sec == 0` for 33,004 of 72,533 genomes). Only ~13% of "rescue" events have posterior ≥ 0.5; ~48% have Stage 0 probability 0. Gaps are KEGG-coverage synthesized, not gapseq; NOGD tables are extrapolated from ≤60 genomes/phylum; ESM-2 3B embeddings were never computed in Stage B (homolog interpolation on CPU). The "four laws" are therefore properties of the heuristic. *Fix (applied):* section reduced to the alignment-derived dark-matter statistics (which do reproduce from the TSVs); Fig. 7 commented out; abstract and Discussion claims removed. *To do:* either run the real integrator over the collection or drop S7/S17/S18 columns derived from Stage C.
6. **Stage 3 120-anomaly benchmark (Table 8, Fig. 5a/b/d).** The manifest `pillar4_proteome_candidates.json` has no generating code; decoys carry `essential_category: "uncovered_essential"` vs `"domain_essential_core"` for all true positives, placeholder pathway names ("Metabolic module 19"), wrong GO labels (GO:0008655 labelled hydrogenase), and "genuine conflicts" that are simply the first GO IDs in the OBO. Resolution JSONL files contain no transcripts. *Fix (applied):* table and figure commented out; the Results keep only the LRO-50 re-ranking, now with single-feature baselines. *To do:* regenerate from real `gspa integrate` anomaly output with a committed script and identical TP/decoy schemas; log transcripts.
7. **LRO-50 agent result.** Sorting the five candidates by the ESM-2 centroid cosine that the agent reads gives Hit@1 96% (MRR 0.977), and the final Stage 1 log-odds alone give 72%; the agent's 82.7% is below one of its own inputs. The 34% "RLGC alone" baseline is the weakest available ranking. *Fix (applied):* both single-feature rows added to Table 5 and the paragraph reworded; the Discussion states that a benchmark not solvable by a single feature is needed.

## B. Real results described incorrectly

8. **Table 1 Stage 0 / GSPA-Seq calibration bug.** `scripts/run_cafa_whole_genome_splits.py:1413-1437` reuses a stale validation alignment (`val_600_vs_train_sensitive.m8`) built for a different eligibility set; only 8/600 validation proteins have DIAMOND hits, so the DIAMOND channel's reliability sits at the floor and its Noisy-OR weight is clipped to 0.05 in every split; the GSPA-Seq stacker is fit on an all-zero DIAMOND feature. Reproduced exactly from the stale file; with a corrected m8 the Stage 0 MF f_w at ≤100% changes from 0.585 to 0.603. *Fix:* key the cache by validation IDs, re-run all six splits (orix), and regenerate Table 1 and S4. Table 1 is kept in the revision but every GSPA/GSPA-Seq number there will change.
9. **"GSPA-Seq improves as homologs are purged" (0.4546 → 0.4895).** Not leakage (targets, IA weights, grid, and training filters verified), but an ensemble-weighting artefact plus an undisclosed split-dependent constant `hom_scale` ∈ {1.0, 0.75, 0.55, 0.38} (`:771`) applied to CNN/ESM channels. Forcing 0.38 at ≤100% raises Stage 0 by +0.024 on identical data. *Fix (applied):* claim removed; constant disclosed in Methods; the margin over GSPA-Seq is presented as the comparison. *To do:* remove or justify `hom_scale` and `fam_candidates` branching on `max_pid`.
10. **Selective reporting of InterPro-LR.** It beats every external baseline on all four homology splits (0.448 → 0.439) and was omitted from Table 1; the text named TALE+ (0.3442) as the strongest baseline at ≤30% while Table 1 itself lists C-HMCNN at 0.3509. *Fix (applied):* InterPro-LR rows added on all splits; sentence removed.
11. **Violations column in Table 1** counts forbidden terms at score ≥ min(τ*, 0.25), not at posterior ≥ 0.50 as captioned; ablation rows share the GSPA-Seq count by construction (priors never touch forbidden terms). *Fix (applied):* caption corrected. *To do:* count at a fixed threshold.
12. **External "retrained" baselines are re-implementations** with ESM-2 3B embeddings as input: DeepFRI has no contact maps (sequence-band smoothing), DeepGraphGO uses a DIAMOND graph, SPROF-GO reshapes a mean embedding into 16 pseudo-tokens, sequences truncated to 256 aa; hard-coded runtimes on checkpoint resume (`train_eval_external_sota_wg_cafa.py:513,935,1123`); `train_ipr.tsv` path may be wrong for DeepGraphGO/DPFunc training on orix. *Fix (applied):* described as re-implementations in Methods and Discussion. *To do:* verify the InterPro path on orix; archive checkpoints and logs.
13. **Perturbation experiment redesigned after first results.** Original run (326c112): soft priors already eliminated all violations and Stage 2A was redundant. Commit 4c5b50e lowered α_cons 3.0 → 0.68 and α_anat 3.5 → 0.68; commit 3310b97 changed injection scores from U(0.55,0.85) to U(0.62,0.90) and added corroborating claims to 60% of pairs. The paper still described the old protocol and claimed hyperparameters "calibrated on E. coli and frozen". *Fix (applied):* current protocol described; "frozen" claim replaced by "applied unchanged within each experiment". *To do:* decide whether to report the first design as well; document when and why α_cons/α_anat were changed.
14. **Leave-subunit-out (Table 3).** "DIAMOND", "Stage 0", and "InterProScan" baselines are the synthetic attenuated inputs (true subunit at raw 0.45/0.50, decoys = unannotated proteins given `uniform(0.42,0.49)` "diamond" claims); 80% of complexes selected to be co-operonic; held-out subunit chosen preferentially co-operonic; McNemar p computed nowhere; an earlier run in `pillar3_report.md` gave operon-vote Hit@1 0.93. *Fix (applied):* rows relabelled, InterPro row removed, caption and text describe the construction. *To do:* add within-operon decoys; add McNemar code.
15. **Eukaryote anatomy inputs (Table 4).** "DIAMOND-BLASTp" and "seven-channel Stage 0" claims are generated from Swiss-Prot truth with `random.uniform(0.80,0.95)` (`run_pillar3_eukaryotic_anatomy.py:403-446`); F-max is computed on the 300 injected proteins only; proteins are the first N in file order. *Fix (applied):* DIAMOND column dropped; caption states the construction. *To do:* run real predictors for the stress cohort or keep it explicitly synthetic in the supplement too.

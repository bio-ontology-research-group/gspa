# Metabolic experiments with masked gene assignments

Status: the production mechanism is implemented and exercised through Python,
the shared Java workflow and a live agent. **Recommendation 12 remains open**:
these checks do not establish held-out function recovery or superiority of an
experiment-selection strategy.

## What changed

`scripts/metabolic_experiments.py` accepts an `assignment_recovery` section.
`scripts/masked_assignment_experiments.py` removes the target's original GPR
before constructing any hypothesis, planner prompt or solver scenario. It drops
the entire AND clause containing the target while preserving alternative OR
clauses. Reactions remain in the network: missing annotation is not pathway loss.
Target aliases, the original model path and the old annotation context are
excluded from the public problem. The masked model gets a content fingerprint.

Each candidate supplies explicit alternative GPR clauses using `MASKED_TARGET`.
Required partner genes remain conjunctive; surviving isozymes remain alternative
routes. Exactly one hypothesis must have no assignments, representing “none of
these candidates”. Only bounded numeric evidence channels and structured
conditions are admitted; answer fields, target identities and free-form candidate
metadata are rejected. A regression changes the hidden original assignment and
verifies identical public inputs and simulated candidate outcomes.

For each selected condition the engine computes a matched control and target
knockout for **every** hypothesis. One solver-call ledger covers all scenarios.
Before selecting a condition, it reserves the maximum cost of the complete
comparison, so candidate ordering cannot determine who gets evaluated. The
fixed, seeded-random, evidence and Qwen selectors use this same budget rule.
The agent receives only public candidate evidence, admissible conditions and
previous conditional results; it can return a condition ID, never executable
code or model changes. An invalid choice or request failure stops the agent arm
and remains visible, without a successful fallback credited to it.

Flux minimization and maximization at an explicit growth floor test alternative
feasible solutions. Product checks support either the growth floor or explicitly
requested maintenance-only feasibility, including nongrowing feasible states.
Infeasibility, absent growth and solver errors remain distinct. Solver exceptions
now consume a call and produce an error record. Product feasibility never implies
expression, and none of these simulations automatically promotes a function or
creates a calibrated probability.

The Java `ExperimentStage` accepts this schema in `--experiment-mode manifest`.
It verifies the input model, requested hypotheses, conditions, medium/objectives,
constraints, budget and completeness of the candidate comparisons. It records the
result and its hash in the stage ledger. These candidate-perturbation results are
not mapped into ordinary FBA confidence features. Automatic construction through
`evidence_guided` is now implemented as described below.

## Manifest form

The ordinary `model`, `baseline`, `objectives`, optional `condition_constraints`
and `config` remain required as appropriate. The private masking boundary reads
`mask_gene`; the agent never receives that field.

```json
{
  "assignment_recovery": {
    "mask_gene": "original_gene_id_or_label",
    "hypotheses": [
      {"id": "H0", "assignments": {}},
      {"id": "H1", "assignments": {"RXN_A": [["MASKED_TARGET"]]}},
      {"id": "H2", "assignments": {"RXN_B": [["MASKED_TARGET", "partner_gene_id"]]}}
    ],
    "conditions": [
      {"id": "C0", "mods": []},
      {"id": "C1", "mods": [{"op": "carbon_swap", "exchange": "EX_ac_e"}]}
    ]
  }
}
```

Hypothesis and condition IDs must be opaque `H<number>` and `C<number>` values.
An optional `evidence` map on each hypothesis accepts `sequence`, `domain`,
`neighborhood`, `recurrence`, `transport` and `bgc` scores in [0,1]. A condition's
`evidence_channels` selects which channels the simple evidence selector sums.
These are supplied evidence scores, not probabilities generated by simulations;
their source and calibration must be established by the caller. No score was
invented for the execution example below.

Run the existing sidecar CLI, or use `gspa integrate --experiment-manifest ...
--experiment-mode manifest`. Set `--experiment-max-experiments` and
`--experiment-max-solver-calls` for the Java route. Selecting a single baseline
condition provides the single-medium control; broader frozen panels, random and
adaptive selections operate on the same condition list and solver budget.

## Automatic construction from this run's evidence

Use `--experiment-mode evidence_guided` with this section in the template:

```json
{
  "assignment_recovery": {
    "mask_gene": "model_gene_id_or_label",
    "candidate_protein": "protein_id_in_this_runs_claims"
  },
  "condition_menu": {
    "carbon_exchanges": ["EX_ac_e"],
    "nitrogen_exchanges": ["EX_nh4_e"],
    "supplement_exchanges": ["EX_vit_e"]
  }
}
```

`candidate_protein` defaults to `mask_gene`; supply it explicitly when the model
and predictor identifiers differ. This is an identity binding, not a function
assignment. Baseline, objectives and model remain required. Optional structured
`assignment_recovery.conditions` extend the generated condition menu, including
background knockouts. The builder assigns opaque IDs to all conditions and
hypotheses. Supplied hypotheses are rejected in this mode; explicit competing
clauses belong to `manifest` mode.

`MaskedAssignmentBuilder` considers complete EC candidates from the raw claims
and structured context for that protein, including unretained weak claims and
context-only candidates with measured support. It uses raw sequence/structure,
domain/motif, genomic-context and BGC channels, plus measured neighborhood and
cohort support. Repeated channel scores take their maximum; no invented score,
Noisy-OR independence or calibrated probability is assigned. Explicit records in
`--experiment-evidence` require `id`, `function_key`, `source`, a supported `type`
and a numeric `score` in [0,1]. Optional exact `substrate_exchange`/`role` or
`product_exchange` fields propose conditions; unknown fields and duplicate IDs
fail. Source records and scores are retained in the stage ledger's private
construction report, not passed to the planner as free text.

EC-to-reaction mappings come from reaction-level SBML EC annotations or exact
reaction-graph IDs present in the model. Gene rules, gene annotations, adjacent
`reactions.tsv`, final integration scores, metabolic/learned inferred claims and
FBA confidence are excluded from candidate construction. A model exported by
this run's refiner cannot be used: its topology may already have been selected
using target annotations. A supplied model likewise needs independently fixed
topology and chemistry for a biological benchmark; the software cannot infer
its curation history. Database/self-hit leakage and clade splits in predictor
inputs still require the benchmark's source audit.

Without structural support, each mapped reaction becomes a target-alone catalytic
hypothesis. Complex-subunit roles require explicit partner support, even when the
candidate also has a catalytic role. Accessory/transporter/regulator-only roles
are excluded. [Raw adapter roles now use the shared role resolver](v3-experiment-role-bridge.md),
with explicit context taking precedence, strict malformed-value rejection and
private source provenance. Derived claims cannot override the raw roles.
Alternative reactions for an EC stay separate; equivalent assignments
share a simulation with every mapping recorded. The null is always included.
Ranking uses the strongest measured channel, then the canonical assignment;
`--experiment-max-hypotheses` caps non-null hypotheses and reports omissions.

Independent structured evidence can now supply `required_genes` and an
`assignment_group`. For example, two records with otherwise required fields can
describe a supported complex activity and a second activity of the same protein:

```json
[
  {"id": "domain_a", "function_key": "query|EC|EC:6.2.1.1",
   "type": "domain", "source": "independent architecture evidence", "score": 0.6,
   "required_genes": ["partner_gene"], "assignment_group": "architecture_a"},
  {"id": "domain_b", "function_key": "query|EC|EC:1.9.3.1",
   "type": "domain", "source": "independent architecture evidence", "score": 0.6,
   "required_genes": [], "assignment_group": "architecture_a"}
]
```

This example is synthetic. `required_genes` resolves declared model gene IDs or
labels into an AND clause with `MASKED_TARGET`; target aliases, unknown genes
and duplicate resolved partners fail. A supplied structural record replaces the
implicit target-alone assumption for that function. Partner knockout conditions
are generated. No partner is inferred from the hidden GPR or from a gene name.
Records sharing a group support a joint hypothesis across at least two distinct
function candidates; individual alternatives remain available. Every group member
must have an eligible mapped candidate and valid clause. An incomplete group is
reported and rejected; contradictory partner lists for the same grouped function
fail. Separate groups/records may express alternative architectures.

Alternative EC-to-reaction mappings form separate combinations. Enumeration is
deterministic and bounded by `--experiment-max-hypotheses` per group, before the
same final non-null cap. The report records total combinations, enumeration
truncation and final omissions. Equivalent clauses are deduplicated, including
`A OR (A AND B) = A`. Independent evidence IDs, groups and mapping provenance stay
in the private construction report. Partners and clauses enter the public problem
because the solver needs them. These fields express supplied evidence; they do
not implement automatic interaction prediction or certify the evidence's origin.

Conditions include the baseline and exact species/cross-reference matches between
candidate reactions and the declared carbon/nitrogen/supplement menu or supplied
oxygen. Supported transport/product hints also contribute conditions. Equivalent
conditions are merged. The sidecar validates exchange boundaries and modifications
before solving. If no candidate maps, the construction report records
`no_admissible_experiment` with zero solver calls; no null-only comparison runs.
For this masked format, `--experiment-max-experiments` counts selected conditions
including the baseline if selected, and each condition compares all hypotheses.

deduplication, invalid/incomplete groups and both caps. The full JVM suite passes
1,026 tests, with two skips and no failures/errors. Two new actual LP regressions
also exposed incorrect separate evaluation of cumulative gene knockouts. Condition
knockouts and the paired target knockout now evaluate their union against the GPR,

## Verification and retained negative result

Eighteen focused Python regressions cover masking, AND/OR semantics, actual LP
outcomes, FVA, product requirements, bounded selection, private/public separation,
agent failures, usage accounting and the actual Python CLI. The existing 53
metabolic tests pass. A production Java workflow test checks the new schema and
rejects a sidecar result whose assignments differ from the request. The full Java
suite passes: 949 tests, two skipped. The benchmark suite passes: 463 tests,
three optional checks skipped.

The broad Python script suite ran 234 tests with 13 optional browser skips before
the final usage-accounting test was added; that added test passes in the focused
suite. Run this script suite separately from Gradle: its visualization tests
invoke Gradle `cleanTest`, which conflicts with a concurrent Java test run. The
Java suite was rerun successfully after that interaction was identified.

The stored iML1515 model was also exercised with the registered `b3919` case,
three hand-specified hypotheses (null, TPI, PGI) and glucose/alanine conditions.
The target GPR was removed first. This is a **mechanism example**, not a blind
candidate-generation or function-recovery benchmark. Both the fixed panel and
live Qwen completed six candidate/condition comparisons in 20 solver calls.
Qwen selected alanine then glucose; its two API requests reported 7,601 prompt
tokens and 16 completion tokens, with no request failures. Total masked-agent
run time, including masking and LP solves, was 123.139 seconds.

`benchmark/v3/check_masked_assignment_cobra.py` independently reads the SBML,
uses COBRA's gene-removal/GPR implementation and GLPK, and replays both controls
and knockouts plus their flux intervals. It agreed on all 12 phenotype states
for each arm, including the computed intervals.

Every candidate still predicts growth under alanine, whereas the registered
experimental knockout label is no growth. That mismatch is retained. No
candidate is certified correct by this example; agreement between two solvers
does not make the underlying biological model correct.

## Remaining acceptance requirements

The full item-12 requirements are unchanged: generate competing assignments from
real sequence/context/role evidence, freeze policies on calibration data, mask
target annotations throughout every evidence source, evaluate unseen organisms
against independent measured phenotypes and hidden function truth, cover
characterized products, and compare all requested methods at equal solver budgets.
Function recovery, harmful assignments, abstention, phenotype agreement and cost
must be assessed separately. Neither this mechanism example nor the earlier
known-function condition-selection study can replace that benchmark. Automatic
complex/multifunction construction and calibrated attribution remain to be integrated.

# Observed HMMER output on synthetic inputs

Generated by `benchmark/v3/generate_hmmer_fixture.py` using installed HMMER 3.4.
`provenance.json` records both executable hashes, versions, actual commands and
all generated artifact hashes. The adapter tests verify the file hashes before
checking parsed domain statistics and query-accession identity.

The alignment is generated with Python random seed 381. `GSPA_TEST_001.1` is a
fixture identifier, not an authentic Pfam family accession. The target sequence
is a member of that synthetic alignment; the poly-alanine control has no hit.
These are execution/format checks, never biological accuracy measurements.

Regenerate into a new directory:

```bash
TMPDIR="$HOME/tmp" python3 benchmark/v3/generate_hmmer_fixture.py \
  --out "$HOME/tmp/new-hmmer-fixture"
```

Set `GSPA_HMMSEARCH_BIN` to run the additional live adapter tests. They call the
real executable through `predictBatch`, including matched, no-hit and malformed
model cases. Three direct-domain cases and one AntiFam case require that variable.
The AntiFam case uses E-value gating for success and confirms that requesting
gathering thresholds from this synthetic model (which has none) reports failure.
It does not establish detection accuracy on real AntiFam families.
